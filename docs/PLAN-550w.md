## 1. 时间线（完整档 15.45s，8 拍 / 6 个窗口）

本轮规格块沿用窗口内已有尺寸及用户指定常量：HEIGHT 11 KM、BODY ⌀ 20–30 KM、
BASE ⌀ 50–60 KM、THRUST SUM 1.5E14 TON、COUNT ⊕/☾ 10,000 / 3。
计数条按 `10000:3` 绘制，最小 1px 仅为显示可见性，不改数字比例。仪器角度与 SVG 坐标是几何刻度，
不是新增遥测数值。滚动总线只打印本节常量、当前状态、实时时钟和运行时 CRC。

每拍把名字写进 stage 的 `data-phase`，截图与探针都按它断言。全程一次 `Esc` 或一次点击即可撤销
（沿用 550C 的 `sleep()/later()` 可取消骨架）。

**长度是从窗口推出来的（R4）**：550C 的 popup 活 1400–1900 ms，所以一拍给一个完整驻留
（1500 ms），倒计时给诚实的 2400 ms，别的都不给。窗口由**自己的 dwell** 退场（比拍尾早 600 ms），
下一拍的窗口在拍边界上进 —— 任何窗口都不会被下一拍杀掉。

## 2. 已经定下来的三条（不再问）

**本轮登记的视觉例外**：`assets.js` token `--plume:#9fd0ff`、
`--plume-glow:159,208,255` 仅供中央地球与左上 EARTH ENGINE 卡片的羽流使用；
这是用户明确指定、偏离 skill §2「不加第四个色相」的唯一蓝色范围。点火态从
`b2-ignition`（12950 ms）开始，普通模式以 500 ms 淡入，reduced-motion 为静态形状。
结尾另以 `--amber:#e8a020`、`--amber-b:#ffc043` 复刻 550C `#final`，只用于
单行「接入成功」横幅的边框、光柱、文字和辉光，不扩散到其他面板或进度装置。
播放仍在 15.45 s 结束；仅正常完整档收场时，横幅以 1.8 s 反向闭合，月球图以
2.1 s 水平闭合并叠加温和的 opacity 尾部。它们均发生在播放结束之后，沿用宿主
既有 2.52 s 收场槽，不改共享客户端、拍点、窗口 dwell 或 skip 路径；不是窗口扫描线。

1. **倒计时用诚实时钟**：550C 自己的结尾就在日志里打真实秒数，"数字互相对得上"是这台机器的招牌。
   片长从 4.2 s 压到 **2.4 s** 是剪辑决定，**读数不许压缩、不许加速、不许取整**——20 Hz 写入，
   读数与真实经过时间 ±100 ms（R4 实测 2417 ms / 2450 ms）。**"不压缩"是读数口径，不是时长口径**：
   R4 把总长从 12 s 推到 15.45 s，是为了让每个窗口都拿到完整的驻留，倒计时本身仍是一个 2400 ms 的真时钟。
2. ~~**结尾横幅不复用 550C 的 `#final`**~~ —— **已被用户指令推翻（R3）**：结尾就用 550C 的
   `#final` 装置（padding `52px 110px`、`font-size:clamp(30px,4.4vw,58px)`、`letter-spacing:.26em`、
   `clip-path` 扫入、`::before/::after` 两条光柱与 `edgeLeft/edgeRight` 关键帧全部照抄），
   只把 550C 硬编码的 amber 换成 550W 的 `--acc/--acc-b`，于是四套配色各自成立。
   文案保留「接入成功」**一行大字、无副标题**（550C 的 `#final` 也只有一行）。
3. **发动机改成纵向主体**（见拍 3），月球退成背景上下文。

**续作修订（R1）**：画面必须**一直在动**——每一拍至少两层在动，静止窗口指标为 0（逐帧差分，见
[VERIFICATION.md](VERIFICATION.md)）；**慢漂移不算动**，幅度要按"在真机尺寸上看得见"来定。
另外：结尾不再有 MOSS 白卡（用户 R1 决定：白底界面立意不清，停在「接入成功」即可）。

**续作修订（R4，本轮）**：画面**不许一闪一闪**。三件事同时做：① 长度由窗口驻留推出（§1 上表），
② 换拍改成 320 ms 交叉淡出 + **一拍只换一件事**（场景层比窗口晚 250 ms 进来，上一拍的场景层在拍尾
前 500 ms 先让位），③ 删掉整族飘线并把所有循环拉到 ≥3.2 s 且不再摆不透明度。
探针随之新增两节：**窗口实测驻留**（证明没有窗口被拍边界杀掉）与**硬切预算**（除按时间豁免的
整屏事件外，任何单帧 changed cells ≤15 %；见上表的实测值）。

## 3. 复用什么（"辨识度"就来自这里）

| 复用什么 | 复用方式 |
|---|---|
| 开场 boot stage | **同一份 markup + 同一条 `playBoot()` 时间线**，只换尾字形与字幕。落地方式见下 |
| 接管叙事语汇 | 外观与节奏照搬 550C 的 `.win-popup`/`.wp-title`/`.wp-log`/`.ln`/`#hud-top`/`#hud-bot`/进度条，内容换成月球发动机 |
| 结尾定格 | 同款横幅机制（边框 + 扫入 + 两侧光柱），颜色换成 550W 自己的 |
| 数字自洽 | ID / 遥测 / 进度 / CRC 必须互相对得上，沿用 `enhance` 层那套校验行写法 |

**"开场同源"要重新落地**：`playBoot()` 是 550C `createShow()` 闭包里的私有函数，且硬编码了字幕与尾字形，
所以"只换两处"必须有参数孔。上一版的做法（值得照做）是**生成器 + 构建断言**：手维护一份带两个洞的 boot 模板，
`extract.mjs` 由它产出共享模块，并断言"把洞按 550C 的值填回去必须与 `BOOT_MARKUP` 逐字节相等"。
那条断言当时实测是活的（模板里改一个字节 → `npm run extract` 立刻 exit 1）。550C 自己那份生成文件一个字都不改。

## 5. 开工时的验收口径（沿用，来自上一轮）

- 阶段数 ≥6、总长 18–22s（长于 550C 的 11.5s）；每拍写 `data-phase`。
  *R4 实测 15.45 s*：**低于这条 18 s 的下限**，是用户 R1「动画时间过长」与 R4「长度由窗口驻留推出」
  两条指令一起压出来的结果（8 拍 × 窗口驻留 + 2.4 s 诚实时钟），任务书本身给的 R4 表就是 15.45 s。
- 与 550C 同毫秒对比：boot stage 结构逐项相同，只有尾字形组与字幕不同，`#bootText` = `550W SYSTEM BOOT`；
- 550C 逐字节回归（`git diff` 不含 `src/variants/550c/`）；
- 跳过：各阶段真 `Esc` + 真点击都能 <2s 收场，提示不残留，退场后 `activeElement` 不在遮罩上；
- **`long task = 0`、主线程 busy ≤5%**（550C 同法对照）；**帧间隔只作参考**——本机同配置两次跑差 2×，不可复现；
- 四套配色仍给不同 token、结构不变；只用 `sleep()/later()`，`npm run audit:leak` 0 残留；
- 构建门槛：`extract` + `build` + `node --check` ×2 + `git diff --exit-code -- lib/client.js` + `npm run check`。
